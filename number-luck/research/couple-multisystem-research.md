## 1) Executive summary

**สิ่งที่พบ (5 ข้อสำคัญที่สุด)**

1. **ระบบวันเกิดพม่า 8 ภาคยืนยันได้ แต่ตารางคู่สมรสยังเป็นคติพื้นบ้านหลักฐานต่ำ**
   วิกิพีเดียภาษาพม่า (နေ့နံ) ให้รายชื่อ **အိမ်ထောင်ရန်** เป็น **คำจำ 4 ชุด**: ဓမ္မာ · သောက · အင်းဝ · ရာဇာ และบล็อกภาษาพม่าร่วมสมัยแสดงชุดเดียวกันบางส่วน.[11][12]
   เมื่อถอดรหัสด้วยระบบ **อักษรประจำวัน (ဝဂ် / wet)** ที่เรา verify ไว้แล้วใน `burmese.py:NAME_LETTERS`
   ได้ผลตรงกับ `COUPLE_CLASH` ที่มีอยู่ **4 จาก 4 คู่พอดี** (ดูตาราง §5.3)
   งานตรวจไขว้เพิ่มเติมพบหนังสือของ Maung Htin Aung ที่ยืนยันระบบ 8 ภาค ดาว สัตว์ และทิศได้ดี แต่ **ยังไม่พบตำราปฐมภูมิ/งานวิชาการที่ยืนยันตารางคู่สมรส 4 คู่** จึงลดความมั่นใจของ `COUPLE_CLASH` เป็น **LOW** และควรแสดงเป็น “คติพื้นบ้านบางแหล่ง” เท่านั้น ไม่ใช้หักคะแนน.[14]

2. **การจับคู่ด้วย "ผังมหาโพติ" ยังใช้ไม่ได้ — ต้องพับเก็บ**
   การค้นรอบนี้ **ยังไม่พบตำราพม่าต้นทางที่ตรวจสอบได้** ว่าให้เทียบผัง 7 เรือนของคนสองคนอย่างไร แหล่งออนไลน์ที่พบเป็นงานร่วมสมัยและมีที่มาไม่พอ → **ห้าม ship** (confidence LOW) ดู §5.5

3. **จีน: 12 นักษัตรใช้ได้แค่ "ชั้นเร็ว" เท่านั้น**
   ความสัมพันธ์กิ่ง 六合/三合/六冲/六害/三刑/破 คำนวณ deterministic ได้จากกิ่งปีเกิด แต่คัมภีร์จีนวางกฎเหล่านี้ในบริบทกว้างของสี่เสาและการสมดุลธาตุ จึง **ห้ามตัดสินจากปีนักษัตรอย่างเดียว**.[5][7][8]

4. **ไทย: "อุทาหรณ์มหาสมพงศ์" เป็น *ตัวอย่างการอ่าน* ไม่ใช่ *ตารางคะแนน***
   ต้นฉบับใน th.wikisource เป็นการสาธิตวิเคราะห์คู่หนึ่งคู่ เรียงข้อสังเกต **๑๐ ข้อ** และใช้ผลเชิงคุณภาพโดยไม่มีสูตรคะแนนตัวเลข จึงต้องนำเสนอเป็น “องค์ประกอบที่ตัวอย่างตำราใช้พิจารณา” ไม่ใช่คะแนน.[6]

5. **ตะวันตก: ต้องแยก 2 เลเยอร์ให้ขาด และเลือกไลบรารีให้ถูกใบอนุญาต**
   Sun-sign เป็น quick view ที่ใช้แค่วันเดือนปี · **synastry จริงต้องมีเวลาเกิด + สถานที่เกิด** สำหรับลัคนา/เรือน
   ⚠️ **Swiss Ephemeris เป็น dual-license (AGPL/professional)** จึงต้อง legal review หรือซื้อไลเซนส์ก่อนใช้ ส่วน **Astronomy Engine** เป็น MIT และเหมาะนำมาทดลอง/benchmark เป็นทางเลือก.[3][10]

**ข้อเสนอเชิงผลิตภัณฑ์**
- แสดงผลเป็น **4 การ์ดแยกศาสตร์** + 1 กล่อง "จุดที่ตรงกัน / จุดที่ขัดกัน" — **ไม่มีตัวเลข % รวมเดียว** (§9)
- ระบบ **degrade อย่างสง่างามตามระดับ input** L1 → L2 → L3 (§3)
- ทำ 3 เฟส: L1 รองรับพม่า/ไทยเฉพาะกฎวันเกิด → L2 ปลดล็อก quick view ครบ 4 ศาสตร์ → L3 เพิ่มลัคนา/เรือน/BaZi 4 เสา/synastry (§11)

## 3) ระดับ input 3 ชั้น

ระบบต้องทำงานได้ทั้ง 3 ชั้น และ **บอกผู้ใช้เสมอว่าตอนนี้อยู่ชั้นไหน + ปลดล็อกอะไรได้อีกถ้าให้ข้อมูลเพิ่ม**

### L1 — รู้แค่ "วันในสัปดาห์" (เช่น "เกิดวันอังคาร")
สถานการณ์จริงที่พบมากที่สุดในตลาดพม่า: คนพม่าทุกคนรู้วันเกิดตัวเอง (วัฒนธรรมแท่นบูชา 8 ทิศรอบเจดีย์) แต่จำนวนมาก **ไม่รู้วันที่แน่นอน**

| ศาสตร์ | ทำได้ | ทำไม่ได้ |
|---|---|---|
| 🇲🇲 พม่า | ✅ โปรไฟล์ 8 ภาค: ดาว ทิศ สัตว์ (วันพุธไม่ทราบช่วงให้เป็น unknown) | ❌ Mahabote/Nakhat ต้องมีปีพม่า · ตารางคู่และยะดะยาสำเร็จรูปยัง HOLD |
| 🇨🇳 จีน | ❌ ไม่ได้เลย | กิ่งปีต้องมีปีเกิด + ขอบปีจีนจริง |
| 🇹🇭 ไทย | ⚠️ ได้ผังทักษารายบุคคล; ตารางคู่มิตร/ศัตรูเป็น MED และรอผู้รู้ตรวจ | ❌ มหาสมพงศ์ ธาตุปี นักษัตร ลัคนา และจันทร์ |
| 🌍 ตะวันตก | ❌ ไม่ได้เลย | ราศีอาทิตย์ต้องมีวันเดือน |

**UI**: ให้การ์ด “โปรไฟล์พื้นฐาน” ของพม่า/ไทยเท่านั้น ยังไม่เรียกว่า compatibility เต็ม; การ์ดจีน/ตะวันตกเป็น “ล็อก 🔒 — ใส่วันเดือนปีเกิดเพื่อปลดล็อก”

ระดับที่ควรตั้งเป็น **default ของฟีเจอร์**

| ศาสตร์ | ทำได้ | ทำไม่ได้ / ต้องเตือน |
|---|---|---|
| 🇲🇲 พม่า | ✅ โปรไฟล์ 8 ภาค + Mahabote classification + Nakhat + ปฏิทินพม่า | ⚠️ พุธเช้า/ราหูแยกไม่ได้ถ้าไม่ทราบช่วง · ตารางคู่ยัง HOLD · ปีพม่าต้องคำนวณด้วย `mmcal` |
| 🇨🇳 จีน | ✅ 3 เสา/6 อักษร + 六合三合六冲六害三刑 + 日主 + 日支; `破` experimental | ❌ ไม่ใช่八字เต็มเพราะไม่มี時柱; แสดง `chart_completeness=6/8` และห้ามอ้างว่าอ่าน用神ครบ |
| 🇹🇭 ไทย | ✅ ผังทักษารายบุคคล; คู่มิตร/ศัตรูระดับ MED หลัง review | ❌ มหาสมพงศ์ ๑๐ ข้อยังทำเป็น engine ไม่ได้; ลัคนา/จันทร์/ธาตุปีต้องรอสูตรที่ยืนยัน |
| 🌍 ตะวันตก | ✅ Sun sign, Mercury, Venus, Mars (คลาดน้อย), Moon sign (คลาดได้ถ้าใกล้เปลี่ยนราศี) | ❌ Ascendant, เรือนทั้ง 12, composite chart แบบ midpoint-house |

**UI**: 4 การ์ดครบแบบระดับข้อมูลไม่เท่ากัน; ตะวันตกเริ่ม Sun-sign overview ส่วน planet-to-planet aspects เปิดเมื่อ engine ผ่าน benchmark และติดป้าย “โหมดไม่มีเวลาเกิด”

### L3 — รู้ "วัน + เวลา + สถานที่เกิด"
ระดับ premium

| ศาสตร์ | สิ่งที่ปลดล็อกเพิ่ม |
|---|---|
| 🇲🇲 พม่า | เวลาเกิดช่วยแยกภาคได้เมื่อผู้ใช้เลือก tradition variant; ถ้าไม่ทราบสำนักให้ถามพุธ/ราหูหรือคืน unknown |
| 🇨🇳 จีน | เสาชั่วโมง (時柱) ครบ 4 เสา โดยประกาศขอบปี/ขอบวัน/DST; จึงเริ่มวิเคราะห์กำลังธาตุได้เต็มขึ้น ไม่ใช่การรับรองความแม่น |

## 4) Research matrix (ตารางแม่)

**คำอธิบายป้าย**
- **Evidence confidence**: `HIGH` = สูตร/การจัดประเภทมีแหล่งที่ตรวจตัวบทได้ชัด · `MED` = มีแหล่งแต่ provenance ไม่ครบ/มีหลายสำนัก · `LOW` = แหล่งรองหรือยังไม่ยืนยัน **ห้าม ship**; ป้ายนี้ไม่ใช่ระดับความแม่นทางวิทยาศาสตร์
- **สถานะ**: `LIVE` = อยู่ใน production แล้ว · `CODE` = มีโค้ดแต่ยังไม่ผูกฟีเจอร์ดวงคู่ · `TODO` = ยังไม่ทำ · `HOLD` = ห้ามทำจนกว่าจะมีแหล่งเพิ่ม

| **ဝံသေ** | พุธเช้า ↔ ศุกร์ | | **တောသူ** | เสาร์ ↔ ศุกร์ |

#### 🧪 การตรวจสอบความสอดคล้องภายใน (internal consistency check)

**ทั้ง 4 หมวด แต่ละหมวดมี 4 คู่ = 8 วันพอดี และแต่ละวันปรากฏ *เพียงครั้งเดียว* ต่อหมวด**
→ ในทางคณิตศาสตร์คือ **perfect matching บนเซต 8 วัน ทั้ง 4 หมวด** ถ้าถอดรหัสผิดแม้พยางค์เดียว โครงสร้างนี้จะพัง (มีวันซ้ำ/วันหาย)
→ นี่เป็น **internal consistency check ที่ดี** สำหรับจับ typo และสนับสนุนว่าการถอดคำจำเป็นไปได้ แต่ไม่แทนตำราต้นทางหรือการตรวจโดยผู้รู้

#### ⚠️ ข้อขัดแย้งที่ต้องเล่าตรง ๆ ไม่ใช่กลบ

- **อังคาร ↔ ราหู** เป็น **ဓာတ်မိတ်** (ธาตุถูกกัน) แต่เป็น **အိမ်ထောင်ရန်** (เรือนไม่ถูกกัน) พร้อมกัน
- **อาทิตย์ ↔ พุธเช้า** ปรากฏทั้งในคำจำ `အိမ်ထောင်ရန်` และ `ဓာတ်ရန်` แต่ห้ามแปลว่า “หนักที่สุด” จนกว่าจะมีตำราอธิบายน้ำหนักของสองหมวด
- แหล่งรอง [achawlaymyar.com](https://achawlaymyar.com/archives/82200) (บล็อกพม่า, ธ.ค. 2022, **ไม่อ้างที่มา**) เอ่ยชื่อรหัสชุดเดียวกัน (ဒန်းလှ, ရာဇာ, သောက, အင်းဝ, ဓမ္မာ) แต่สรุปคู่วันบางบรรทัดขัดกันเอง → **ใช้เป็นเพียงตัวยืนยันว่าชุดนี้แพร่หลายจริงในหมู่คนพม่า ไม่ใช้เป็นแหล่งตัดสิน**

**ข้อเสนอ product**: HOLD ทั้งสามตารางไว้ก่อน หากภายหลังมีผู้รู้หรือตำราต้นทางยืนยัน จึงค่อยแสดงเป็นหัวข้อ “คติการครองคู่” และ “คติธาตุ” แยกกัน โดยไม่ยุบเป็นคะแนน (`အိမ်ထောင်` หมายถึงการแต่งงาน/ครองคู่ ไม่ใช่ “เรือน” ทางโหราศาสตร์)

### 5.4 Mahabote classification รายบุคคล *(สูตร HIGH; การขยายเป็นผัง/คำทำนายต้องตรวจ)*

สูตรที่ตรวจได้จาก `mmcal` คือ `classification = (Myanmar year - weekday_index) mod 7` และคืนหนึ่งใน Binga, Atun, Yaza, Adipati, Marana, Thike หรือ Puti สูตรนี้ยืนยัน **ประเภทของบุคคลหนึ่งราย** แต่ไม่ได้ยืนยันการวางดาวเต็ม 7 เรือนหรือคำแปลอังกฤษทุกเรือนในโค้ด Number Luck.[2]

⚠️ **จุดตัด 15 เม.ย. เป็นการลดรูป** — สงกรานต์พม่าจริงแปรผันรายปี (2026 = 17 เม.ย.) → **คนเกิด 13–17 เม.ย. ผังจะผิดได้ทั้งผัง** ต้องเรียก `mmcal.py` ตัดปีแทน (bug นี้บันทึกไว้แล้วใน research รอบ 2 แต่ยังไม่แก้)

**ใช้ในฟีเจอร์ดวงคู่ได้อย่างไร**: แสดง classification ของคน A และ B แยกกันโดยไม่สร้างความสัมพันธ์ระหว่างประเภท หากจะใช้คำอย่าง “เรือนทรัพย์/ชื่อเสียง” ต้องตรวจ mapping กับตำราพม่าต้นทางก่อน

### 5.5 🛑 มหาโพติจับคู่ — ทำไมต้องพับเก็บ *(LOW — HOLD)*

สูตร "จับคู่มหาโพติ" ที่พบตามเว็บ (เทียบเรือนของสองฝ่าย / นับดาวร่วมเรือน / ตีความเรือน 7 เป็นเรือนคู่ครอง) มีปัญหา 4 ข้อ:

1. การค้นรอบนี้ **ยังไม่พบตำราพม่าต้นทางที่ตรวจสอบได้** ซึ่งระบุว่าใช้ผัง 7 เรือนตัดสินคู่ครอง แหล่งร่วมสมัยที่พบยังไม่พอสำหรับสร้างกฎ production และบางแหล่งมีลิขสิทธิ์
2. แหล่ง `mmcal` ให้เพียง classification รายบุคคล ไม่ได้ให้ตาราง synastry หรือการเอาเบอร์โทรศัพท์ไปเติมเรือน
3. สูตรใช้ปีพม่าและ weekday เป็นการจำแนกที่ค่อนข้างหยาบ จึงไม่ควรขยายเป็นคะแนนความสัมพันธ์โดยไม่มีแหล่ง
4. **ถ้า implement เราจะกลายเป็นผู้ประดิษฐ์กฎเอง** ซึ่งขัด P2

**สิ่งที่ต้องหาให้ได้ก่อนปลดล็อก**: ตำราโหรพม่าภาษาพม่า (မဟာဘုတ်) ที่พูดเรื่องคู่ครองโดยตรง หรือบทความวิชาการฉบับเต็ม งาน *On Burmese Horoscopes* ถูกพบในรอบนี้แต่เข้าถึงได้เพียง metadata/preview จึงใช้เป็นแผนที่ค้นต่อ ไม่ใช้ยืนยันสูตร.[13]

### 5.6 ป้ายวันสำหรับกิจกรรมของคู่ *(สูตร HIGH; ฤกษ์สมรส LOW–MED)*

`mmcal.py` พร้อมคำนวณป้ายปฏิทิน เช่น ยัตยาซา / เปียตะดา / วันอุโบสถ / ทิศหัวนาค แต่ป้ายเหล่านี้เป็น **คุณภาพวันทั่วไป** ไม่ได้ทำให้วันนั้นเป็นฤกษ์เฉพาะคู่โดยอัตโนมัติ.[2]
→ นำไปเป็นตัวกรองหนึ่งของฟีเจอร์ฤกษ์หมั้น/แต่งได้ หลังเพิ่มกฎไม่ชงวันเกิดทั้งสองฝ่ายและให้ผู้รู้ตรวจ ไม่ควรเรียกว่า “ฤกษ์ของคู่นี้” จากป้ายวันเพียงชุดเดียว

### 5.7 Nakhat 3 ประเภท *(สูตร HIGH; compatibility LOW)*

`mmcal` ให้ `nakhat = Myanmar year % 3` เพื่อจำแนก Ogre/Deva/Human แสดงเป็นข้อมูลพื้นดวงรายบุคคลได้ แต่ยังไม่พบตารางต้นทางที่ยืนยันว่าประเภทใดควรหรือไม่ควรแต่งกัน จึงห้ามสร้างคะแนนคู่จาก Nakhat

### 5.8 Yadaya *(มีจริง HIGH; สูตรสำเร็จรูปในแอป LOW)*

งานวิชาการร่วมสมัยยืนยันว่า yadaya เป็นพิธีเชิงป้องกัน/แก้ผลร้ายที่โดยปกติพึ่งคำแนะนำเฉพาะจากผู้รู้ แต่ยังไม่พบสูตรสากลว่า `ဂြိုဟ်သက်` ต้องกลายเป็นจำนวนสิ่งของหรือสัตว์ในพิธี.[15] ดังนั้น `yadaya_prescription()` ปัจจุบันต้อง HOLD; หากมีคำแนะนำให้เรียกว่า “กิจกรรมเชิงสัญลักษณ์ที่ Number Luck เรียบเรียง” และใช้เฉพาะกิจกรรมปลอดภัย ไม่ปล่อยสัตว์หรือรับรองผล

## 6) ศาสตร์จีน 🇨🇳

### 6.1 ชั้นเร็ว (Quick layer) — ความสัมพันธ์ 12 กิ่ง *(HIGH ในการคำนวณ)*

ใช้ **กิ่งปีเกิด (年支)** ของสองฝ่ายเทียบกฎตามตาราง การจับคู่เป็น deterministic mapping แต่ **ไม่ใช่ความแม่น 100% ของคำทำนาย**

| กฎ | จำนวนคู่ | โครงสร้าง | คู่ทั้งหมด | ความหมายโดยย่อ (paraphrase) |
|---|---|---|---|---|
| **六合** ลิ่วเหอ | 6 | ผลรวม index = คงที่ | 子丑 · 寅亥 · 卯戌 · 辰酉 · 巳申 · 午未 | ประสานกัน ดึงดูด ช่วยกันปิดจุดอ่อน |
| **三合** ซานเหอ | 4 ชุด × 3 | ห่างกัน 4 กิ่ง | 申子辰(น้ำ) · 亥卯未(ไม้) · 寅午戌(ไฟ) · 巳酉丑(ทอง) | คนสองคนบอกได้เพียงว่า “อยู่ในกลุ่มเดียวกัน/มี 2 ใน 3 กิ่ง”; ยังไม่ใช่三合局เต็ม |
| **六冲** ลิ่วชง | 6 | ตรงข้าม 180° (ห่าง 6) | 子午 · 丑未 · 寅申 · 卯酉 · 辰戌 · 巳亥 | ปะทะ เปลี่ยนแปลง แรงชนแรง |
| **六害** ลิ่วไห่ | 6 | ผลรวม index = คงที่ (อีกแกน) | 子未 · 丑午 · 寅巳 · 卯辰 · 申亥 · 酉戌 | บั่นทอนเงียบ ๆ น้อยใจ ระแวง |
| **三刑** ซานสิง | 3 ชุด + 自刑 | — | 寅巳申 · 丑戌未 · 子卯 · 自刑(辰午酉亥) | ลงโทษ/ขัดแย้งซ้ำซ้อน |
| **破** พั่ว | 6 | ตารางร่วมสมัย | 子酉 · 丑辰 · 寅亥 · 卯午 · 巳申 · 未戌 | หลักฐานเก่าที่ตรวจได้อ่อนกว่ากฎอื่น ใช้เป็นข้อมูลทดลองเท่านั้น |

⚠️ **ข้อควรระวังที่ต้องเขียนลง UI**
- **三刑 มีหลายสำนัก** — ชุด 子卯 บางตำราเรียก 無禮之刑, บางฉบับจัด 自刑 ต่างกัน → ต้อง **ประกาศว่าเรายึดสำนักไหน** และอย่าผสมสำนัก
- เมื่อคู่รักมีเพียงสองกิ่งจากชุด **三合/三刑 สามกิ่ง** ต้องบอกว่าชุดยังไม่ครบ ห้ามประกาศว่าเกิด局เต็ม.[16]
- **寅亥 และ 巳申 เป็นทั้ง 六合 และ 破** พร้อมกัน — ต้องแสดงทั้งคู่ ไม่หักล้างกันเอง (ตำราเองก็มองเป็นสองด้าน)
- **ขอบปีต้องประกาศสำนัก** ว่าตัดที่ 立春 หรือวันขึ้นปีจันทรคติ `lunar-python` คำนวณข้อมูลได้ แต่โปรแกรมต้องเลือก API/กติกาให้ชัด ห้ามใช้ 1 ม.ค. โดยไม่อธิบาย

### 6.2 🛑 ทำไมชั้นเร็วยัง **ไม่ใช่** "ดวงคู่ตามศาสตร์จีน"

ปีนักษัตรคือกิ่งเดียวจาก **8 อักษร (八字)** — ใช้ตัดสินคู่ครองเพียงตัวเดียวคือการทิ้งข้อมูล 7/8 ส่วน ตำราคลาสสิกทั้ง 三命通會 (หมิง, 萬民英), 神峰通考 (หมิง, 張楠) และ 滴天髓闡微 ไม่ได้อ่านดวงจากกิ่งปีเดี่ยว ๆ; Hong Kong Observatory อธิบายว่า干支ของปี เดือน วัน และเวลารวมกันเป็น八字.[19]

**ดวงคู่ตามศาสตร์จีนของจริงต้องดู**

| องค์ประกอบ | คืออะไร | ทำไมสำคัญต่อดวงคู่ | input ที่ต้องใช้ |
|---|---|---|---|
| **4 เสา (四柱)** | ปี/เดือน/วัน/ชั่วโมง × (ก้าน+กิ่ง) = 8 อักษร | ฐานของทุกอย่าง | L3 (เสาชั่วโมงต้องมีเวลา) |
| **日主 / 日元** (ก้านเสาวัน) | ธาตุที่แทน "ตัวเรา" | ความเข้ากันวัดจากธาตุตัวเอง ↔ ธาตุอีกฝ่าย | L2 |
| **日支 = 配偶宮** (กิ่งเสาวัน) | **เรือนคู่ครอง** | ตำแหน่งที่ตำราใช้อ่านเรื่องคู่โดยตรง | L2 |
| **旺衰 กำลังธาตุ** | ธาตุตัวเองแข็ง/อ่อนตามฤดู (月令) และการหนุน/ทอน | เปลี่ยนคำตัดสินได้ **กลับด้าน** | L2 บางส่วน / L3 เต็ม |
| **用神** (ธาตุที่ต้องการ) | ธาตุที่ทำให้ดวงสมดุล | ถ้าอีกฝ่ายพา 用神 มาให้ = คู่ที่เกื้อกัน | L3 |
| **十神** (ทศเทพ) โดยเฉพาะ 正官/正財 | เครื่องหมายคู่ครอง (หญิงดู 官, ชายดู 財) | บอกลักษณะความสัมพันธ์ | L2/L3 |

บรรทัด十神ด้านบนเป็นกรอบเพศตามตำราคลาสสิก โหมดมาตรฐานของ Number Luck ควรเป็นกลางทางเพศและเน้น Day Master, spouse palace, element flow และความสัมพันธ์ระหว่างเสา ส่วนการอ่านบทบาทชาย/หญิงให้เป็น historical/optional mode

**ตัวอย่างที่แสดงว่าปีนักษัตรอย่างเดียวหลอกได้**: คู่ที่กิ่งปี **ชง (六冲)** กัน แต่ 日主 ของทั้งสองเป็นธาตุที่หนุนกัน (เช่น น้ำหล่อไม้) และกิ่งเสาวันเข้า 六合 กัน → ตำราจะอ่านว่า "กระทบภายนอกแต่ผูกพันภายใน" ซึ่ง **ตรงข้ามกับผลของชั้นเร็ว**

**ข้อเสนอ UI (สำคัญมาก)** — การ์ดจีนต้องมี 2 ระดับที่มองเห็นชัดว่าเป็นคนละอย่าง:
```

## 7) ศาสตร์ไทย 🇹🇭

### 7.1 แกน: อุทาหรณ์มหาสมพงศ์ *(MED — หน้าออนไลน์ไม่มี provenance ครบ)*

แหล่ง: [th.wikisource — คัมภีร์โหราศาสตร์ไทยมาตรฐานฉบับสมบูรณ์ / อุทาหรณ์มหาสมพงศ์](https://th.wikisource.org/wiki/คัมภีร์โหราศาสตร์ไทยมาตรฐานฉบับสมบูรณ์/อุทาหรณ์มหาสมพงศ์)

**สิ่งที่ต้นฉบับเป็นจริง ๆ** — คำว่า "อุทาหรณ์" แปลว่า **ตัวอย่าง** ต้นฉบับคือการ **สาธิตอ่านดวงสมพงศ์ของคู่หนึ่งคู่** โดยเรียงข้อสังเกตเป็นข้อ **๑–๑๐** แล้วสรุปด้วยถ้อยคำเชิงคุณภาพ เช่น "ดีนัก" "เจริญยั่งยืนดี"

> 🛑 **ต้นฉบับไม่มีตัวเลขคะแนน ไม่มีน้ำหนักถ่วง ไม่มีเปอร์เซ็นต์**
> ห้ามสร้างสูตร "ข้อละ 10 คะแนน = 100" แล้วอ้างว่าเป็นตำราไทย — นั่นคือของที่เราแต่งเอง

### 7.3 ทักษา — คำนวณรายบุคคลได้; cross-chart เป็นการประยุกต์

งานวิชาการด้านทักษายืนยันลำดับดาว `1 → 2 → 3 → 4 → 7 → 5 → 8 → 6` และลำดับภูมิ `บริวาร → อายุ → เดช → ศรี → มูละ → อุตสาหะ → มนตรี → กาลกิณี` จึงคำนวณผังทักษารายบุคคลได้.[17]

**ข้อจำกัด**: การเทียบว่า “ดาววันเกิดของ B ตกภูมิใดในทักษาของ A” และย้อนกลับ เป็นการประยุกต์ของ Number Luck ไม่ใช่สูตรสมพงศ์มาตรฐานที่พบในบทความดังกล่าว ต้องติดป้ายและไม่สร้างคะแนน

### 7.4 คู่มิตร–คู่ศัตรูดาวแบบไทย *(MED)*

- คู่มิตรที่พบตรงกันในแหล่งทั่วไป: `1–5, 2–4, 3–6, 7–8`
- คู่ศัตรูที่พบตรงกัน: `1–3, 4–8, 6–7, 2–5`

หอสมุดแห่งชาติมีระเบียน “ตำราดูคู่มิตรและศัตรู” จริง แต่ไม่มีไฟล์สแกนให้ตรวจสูตรภายใน จึงใช้ได้เพียง confidence ระดับกลางและต้องอยู่ในโมดูลไทย.[18] คู่ `2–8` และ `3–7` ที่อยู่ในโค้ดเดิมยังไม่มีหลักฐานจากรอบนี้

### 7.5 ข้อจำกัดของฝั่งไทยที่ต้องยอมรับ

1. ก่อนคำนวณลัคนา/สมผุส ต้องระบุว่าคัมภีร์ฉบับที่เลือกใช้ระบบใดและค่าอายนางศใด ห้ามเอาราศี tropical จากการ์ดตะวันตกมาใช้ในการ์ดไทยโดยไม่ตรวจ
2. อุทาหรณ์ฯ เป็นตัวอย่าง **1 คู่** — การสรุปเป็นกฎทั่วไปทุกข้อคือการตีความของเรา ต้องติดป้ายให้ชัด
3. หน้า Wikisource ที่ใช้ติดป้ายว่า **“ไม่มีที่มา”** จึงต้องตรวจชื่อฉบับพิมพ์ ผู้เรียบเรียง ปีพิมพ์ และสถานะสิทธิ์ แม้เนื้อหาจะดูเป็นคัมภีร์เก่า ควรอ้างหน้าและ paraphrase เท่านั้นจนกว่าจะยืนยัน provenance

## 8) ศาสตร์ตะวันตก 🌍

### 8.1 แยก 2 เลเยอร์ให้ขาด

| | **เลเยอร์ A: Sun-sign quick view** | **เลเยอร์ B: Full synastry** |
|---|---|---|
| input | วันเดือนปี (L2) | วัน + **เวลา** + **สถานที่** (L3) ทั้งสองฝ่าย |
| ใช้อะไร | ราศีอาทิตย์ 12 ราศี + ธาตุ/คุณลักษณะ | ดาวส่วนบุคคล 5–6 ดวง + ลัคนา + มุม + เรือน |
| ความละเอียด | 12 × 12 = 144 กรณี | ต่อเนื่อง (องศา) แทบไม่ซ้ำกัน |
| ตำแหน่งใน UI | โชว์ทันที ฟรี | ต้องกรอกเวลา/สถานที่ก่อน |
| ป้ายกำกับ | "มุมมองเร็ว — โหราศาสตร์ตะวันตกจริงไม่ตัดสินจากราศีอาทิตย์อย่างเดียว" | "ดวงคู่เต็มรูปแบบ" |

**เลเยอร์ A ประกอบด้วย** Sun sign, ธาตุ และ Modality เป็นหลัก ส่วนมุมราศีใช้เฉพาะ major aspects ใน MVP:
| ระยะ | มุม | ชื่อ | ธาตุ | ความหมายย่อ (paraphrase) |
|---|---|---|---|---|
| 0 | 0° | Conjunction | เดียวกัน | เหมือนกันมาก ทั้งข้อดีข้อเสีย |
| 2 | 60° | Sextile | เข้ากันได้ | ส่งเสริมกัน ต้องออกแรงนิดหน่อย |
| 3 | 90° | Square | ขัดกัน | ตึงเครียด แต่กระตุ้นการเติบโต |
| 4 | 120° | Trine | ธาตุเดียวกัน | ราบรื่นที่สุดตามธรรมเนียม |
| 6 | 180° | Opposition | ตรงข้าม | ดึงดูดและปะทะพร้อมกัน |

Ptolemy, *Tetrabiblos* (Project Gutenberg) เป็นหลักฐานประวัติศาสตร์ของ major aspects ในการพิจารณาคู่ แต่คำอธิบายร่วมสมัยและชุด orb ต้องมีแหล่งแยกและเขียนใหม่.[9]

### 8.2 เลเยอร์ B — องค์ประกอบและ input ที่ต้องใช้

| องค์ประกอบ | อ่านอะไร | input ขั้นต่ำ | ความคลาดถ้าไม่มีเวลาเกิด |
|---|---|---|---|
| **Sun ☉** | แก่นตัวตน เป้าหมายชีวิต | L2 | เกือบไม่คลาด (~1°/วัน) |
| **Moon ☽** | อารมณ์ ความรู้สึกปลอดภัย ชีวิตประจำวัน | L2 หยาบ | **~13.2°/วัน** → ผิดราศีได้บ่อย ⚠️ |
| **Mercury ☿** | วิธีสื่อสาร คุยกันรู้เรื่องไหม | L2 | น้อย (ยกเว้นวันเปลี่ยนราศี) |
| **Venus ♀** | รูปแบบความรัก รสนิยม การให้ | L2 | น้อย |
| **Mars ♂** | แรงขับ เซ็กส์ วิธีทะเลาะ | L2 | น้อยมาก |
| **Ascendant ↑** | ภาพแรกและวิธีเข้าหาโลกตามคติ | **L3 บังคับ** | ไวต่อเวลาเกิดมากและอัตราการเคลื่อนขึ้นกับละติจูด/ราศี → **ไม่มีเวลา = คำนวณไม่ได้** |
| **Aspects** | มุมระหว่างดาวสองผัง + orb | L2 (ดาว) / L3 (ลัคนา) | ตาม orb ที่เลือก |
| **Houses / overlays** | ดาวเขาตกเรือนไหนของเรา = เขามีผลด้านใดในชีวิตเรา | **L3 บังคับ** | ต้องมีลัคนา |
| **Composite** | ผังของ "ความสัมพันธ์" เอง (midpoint) | **L3** สำหรับเวอร์ชันมีเรือน | midpoint ดาวทำได้ที่ L2 แต่ midpoint ลัคนา/MC ต้อง L3 |

Synastry เปรียบเทียบดวงกำเนิดสองคน ส่วน midpoint composite และ Davison เป็น comparative techniques คนละชนิด ต้องแยกแท็บและคำอธิบาย ไม่ใช้ composite แทน synastry.[23]

**เรื่อง orb (สำคัญ ห้ามข้าม)**: วงการไม่มีมาตรฐานกลาง จึงต้องประกาศว่าเป็น product convention ข้อเสนอ strict/readable v1 คือ conjunction/opposition 6°, square/trine 5°, sextile 3°; เพิ่ม 1° เมื่อมี Sun/Moon หรือ angle ที่เวลาเกิดแม่น และจำกัด outer–outer แคบลง แสดง orb จริงทุกครั้ง เช่น `Moon trine Venus, orb 1°24′`.[22]

### 8.3 ⚠️ กับดักการคำนวณเรือน (L3)

## 9) การนำเสนอผลรวม — ทำไมห้ามมี % เดียว

### 9.1 เหตุผล

1. **หน่วยวัดไม่ตรงกัน** — พม่านับเป็น "คู่/ไม่คู่" (ordinal 5 ระดับ), จีนนับเป็นชนิดความสัมพันธ์ของกิ่ง (categorical), ไทยเป็นข้อสังเกตเชิงคุณภาพ, ตะวันตกเป็นองศาต่อเนื่อง → เฉลี่ยรวมไม่มีความหมายทางคณิตศาสตร์
2. **น้ำหนักถ่วงจะเป็นของเราล้วน ๆ** — ไม่มีตำราใดในโลกบอกว่า "พม่า 40% จีน 30%" → ผิด P1 และ P2
3. **ตัวเลขเดียวสร้างภาพลวงว่าแม่นยำ** — "78%" ฟังเหมือนวัดได้ ทั้งที่เป็นความเชื่อ ผิด P5
4. **เสียคุณค่าเชิงผลิตภัณฑ์** — จุดที่ 4 ศาสตร์ **ขัดกัน** คือเนื้อหาที่น่าสนใจที่สุด การเฉลี่ยทำให้หายไปหมด

> ⚠️ ของเดิมใน `app.py` หน้าดวงคู่ตอนนี้ใช้ `overall = bd_score*0.7 + np_score*0.3` และตัวเลขฐาน (88/80/72/62/45/35) เป็นค่าที่ **ทีมกำหนดเอง** — เมื่อทำฟีเจอร์ 4 ศาสตร์ ควรถือโอกาสเลิกใช้ตัวเลขเดี่ยวนี้ หรืออย่างน้อยติดป้ายชัดว่า "เกณฑ์ของทีมงาน"

by_category = group_factors(results, key=lambda f: f.category)
shared_themes = []
contrasts = []
for category, factors in by_category.items():
    traditions = unique(f.tradition for f in factors)
    polarities = set(f.polarity for f in factors)
    if len(traditions) >= 2 and len(polarities) == 1:
        shared_themes.append((category, polarities.pop(), traditions))
    elif "supportive" in polarities and "challenging" in polarities:
        contrasts.append((category, factors))

# ไม่โหวต ไม่เฉลี่ย และไม่สร้าง verdict รวม
# แสดงชื่อศาสตร์และกฎต้นทางใต้ทุก shared theme / contrast
```

### 10.2 โครงสร้างข้อมูล
```python
@dataclass
class Person:
    date: datetime.date | None      # None = L1
    weekday: str | None             # 'sun'..'sat' (L1 ใส่ตรง)
    wednesday_sector: str | None = None # 'mercury'|'rahu'|'unknown'
    tradition_variant: str | None = None# เช่น 'maung_htin_aung_18h'
    time: datetime.time | None = None      # L3
    time_accuracy: str = 'unknown'         # record|approximate|unknown
    tz: str | None = None                  # 'Asia/Yangon' (L3)
    lat: float | None = None; lon: float | None = None   # L3
    sex: str | None = None                 # optional historical mode เท่านั้น
    name: str | None = None                # ห้ามใช้กับ “นามกำเนิด” จนกว่าสูตรจะยืนยัน

    @property
    def level(self) -> int:                # 1 | 2 | 3
        if self.time and self.lat is not None: return 3
        if self.date: return 2
        return 1

@dataclass
class Rule:            # หนึ่งกฎที่ยิงโดน
    key: str           # 'aimdaung_yan' | 'liuhe' | 'thai_10_1' | 'venus_trine'
    label_i18n: str    # key เข้า i18n.py (th/en/mm)
    polarity: str      # 'supportive'|'mixed'|'challenging'|'neutral'
    source_url: str
    evidence_confidence: str # ความชัดของแหล่ง/สูตร ไม่ใช่ความแม่น
    input_quality: str        # 'exact'|'partial'|'ambiguous'
    status: str               # 'PRODUCTION'|'EXPERIMENTAL'|'HOLD'

@dataclass
class TraditionResult:
    tradition: str            # 'burmese'|'chinese'|'thai'|'western'
    summary_label: str | None # ข้อความสรุป ไม่ใช่คะแนน; None หากปัจจัยผสมกันมาก
    rules_hit: list[Rule]
    locked: list[str]         # สิ่งที่ทำไม่ได้เพราะ input ไม่พอ
    needs_level: int          # ต้องถึง L เท่าไรถึงปลดล็อกครบ
```
**ไม่มีฟิลด์ `score: float` โดยเจตนา** — เพื่อไม่ให้ใครเผลอเอาไปเฉลี่ย
